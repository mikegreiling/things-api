## small code — unblocked, low effort

- **Hide `--op-id` from variadic move/reorder help (help/runtime contract bug).** Current `things todo move --help`, `things project move --help`, and `things reorder --help` all advertise the shared `--op-id <key>` option, but execution categorically refuses it before dispatch: `things todo move some-uuid --to-project x --op-id k --json` exits 2 with “`--op-id` is not available on a variadic move/reorder (a multi-leg compound) — express it as `things batch` with a per-line op_id for idempotent resubmission.” The runtime restriction is intentional in idempotency phase 1 and already has a rejection test (`test/cli/single-op-idempotency-cli.test.ts`); the public help is therefore lying. Register write flags per command capability (or otherwise suppress the unsupported option) so these compound commands omit `--op-id`, and add help-surface regression coverage for all move/reorder spellings while retaining the runtime refusal as defense in depth.
- **`things repeaters` — a library-wide template listing.** Repeating templates are nearly invisible to reads: search matches a repeater's open *instances* but never the template; the template's full rule is reachable only via `show <template-uuid>`, whose uuid you can only learn from an area view. RS6 already closed most of the read-shape gaps; the residual is a dedicated listing (template uuid + full rule, library-wide). Small, high agent value. *(Note: "let search match templates" was floated but is unverified — treat as a separate probe, not part of this item.)*
- **Undo session-qualified actors (`mcp:<session>`).** The optional fourth layer of undo actor-scoping: session-qualified actors with prefix matching on `by:`. PARKED-CONDITIONAL — build only if parallel agents become real.
- **`--markdown` output mode.** A third render target alongside TTY and `--json`: YAML frontmatter for metadata, `- [ ]`/`- [x]` for to-dos/checklists, `##` for Things headings, project title as `#`. It is a RENDERING of the same data, never a third contract (derive from the JSON-shaping layer, drift-tested); NO markdown import/roundtrip in scope. Likely sweet spot: agent contexts + piping into notes. *(Mike: do NOT spec yet — a future design discussion.)*
- **Tag shorthand — `things @errand` (explicit-only).** Bare-noun routing of a tag NAME is rejected (collision surface; a rename could silently flip which view renders — see [design/decisions.md](design/decisions.md)). The open sliver is whether an explicit sigil (`things @errand` → `things anytime --tag errand`) is worth it at all, or whether tags stay explicit-only via `--tag`. Needs deliberate design; not scheduled.
- **Stale-DB stderr warning on ordinary reads.** `doctor` answers "data may be stale — Things is not running" on demand (sync-health section); whether every read should emit a one-line stderr nag is a separate UX call that overlaps the display-preferences / chrome decisions above.
- **Cross-terminal glyph audit.** The CLI glyph language (`src/cli/glyphs.ts` — checkbox marks, pie quarters, chips, `★/⏾/≡`) was chosen on one macOS font stack. Audit rendering across emulators/fonts (Terminal.app, iTerm2, Ghostty, kitty, VS Code, Warp × SF Mono/Menlo/JetBrains Mono/a Nerd Font, plus a CJK-wide `ambiguous=double` config and a `NO_COLOR`/piped pass). Watch for tofu on `⏾` (U+23FE) and the pie quarters, double-width drift breaking column alignment, dim-on-light legibility. Every glyph is a `glyphs.ts` constant, so retuning is one file.

## feature design — wants an ideation round before code

- **Change-watch / poll mode (`things watch`, name TBD) — v1.0 GATE (maintainer, 2026-08-11; see roadmap v1.0 checklist).** Motivating workflow: an agent creates a little project, schedules it into Today, then kicks off a long-running `things` invocation that WATCHES that project specifically and reacts when Mike completes/adds/removes tasks in it — without firing on unrelated library changes. Shape: a read-only long-running CLI command (MCP story later) scoped to one container/view (`--project <ref>`, maybe `--today`), emitting NDJSON events `{event: added|removed|completed|canceled|modified, uuid, title, …}`, plus a blocking `--once`/`--until <condition>` mode (the natural fit for an agent's "wait for change" step and `run_in_background` Bash tasks). Raw material banked: `main.sqlite-wal` mtime advances on every write (the cheap wake signal); on wake, diff a scoped member snapshot (uuid set + status/stopDate/index per member). Constraints: READS ONLY; keep the ONE stable command/binary shape on the prod host (ride the existing library read path); define behavior when Things isn't running (DB frozen — the doctor sync-health signals apply); bounded exit conditions. **Constraint from the ledger (§9r, broadened by [reference/timestamps.md](reference/timestamps.md) §2):** the umd-SILENT class is much larger than reorders — tag rename/delete, area-delete of logged members, log sweep, template writes, and more never bump `userModificationDate` — so a naive `modified` detector keyed on umd will miss whole change families; the member-snapshot diff must compare the actual fields (index/order, tags, FKs), never umd alone. Open questions: `modified` granularity (title/when/notes — all or opt-in?), whether whole-project-completion is a first-class terminal event, how undo-driven reversals read in the stream.
