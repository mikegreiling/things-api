# Assumption register — the behavioral laws shipped mutations depend on

Every shipped write scope, read derivation, and write guard rests on a **behavioral assumption** about how Things 3 responds to an automation command — an insertion geometry, a preservation set, a refusal ground. The schema fingerprint ([drift-runbook](../lab/drift-runbook.md)) catches a *schema* change; it is BLIND to a *behavioral* change (an app update can move an insertion law with zero schema delta). This register is the countermeasure: one row per law a shipped surface relies on, each pinned to a **recurring lock** (the check that fails when the law breaks) so a Things update that moves the surface is caught, not silently trusted.

**Policy (suite-audit sibling):** an op ships with a recurring live check — and a **LAW** ships with a register row + lock. Re-certifying after a Things update = walk this register (drift-runbook step 3) and confirm every lock still passes; any row whose lock is a GAP is re-verified by hand against its campaign doc.

**Lock kinds (weakest → strongest for drift):**

- **suite row** (`lab/suites/*.json`, `npm run lab:regress`) — re-runs the raw wire command against a fresh clone of the golden and asserts the DB effect. **The only lock that sees APP-behavior drift.** Cited as `o-suite O19` etc.
- **e2e step** (`lab/guest/e2e-write-smoke.sh`) — drives the shipped CLI end-to-end against the real app; sees drift through the whole planner→vector stack.
- **engine test** (`test/engine/*.ts`) — drives the real compiler/pipeline against a FAKE executor + fixture DB. Catches a COMPILER regression (we emit the wrong wire command); **cannot** see app-behavior drift.
- **unit pin** (`test/unit/*.ts`) — a derivation/predicate over fixture rows. Same blindness as engine.
- **certification runbook** (per-Things-version, human/VNC) — the recurring lock for ui-vector (HID/AX) laws that `lab:regress` cannot drive headlessly.
- **runtime canary** — a per-call guard in the shipping binary that fails closed when a precondition vanishes (the sdef reorder-command check; the app-version behavioral-drift notice, §doctor).

A law whose ONLY lock is engine/unit is flagged **⚠ no live lock** — that is the gap list. A GAP is not always closable (some laws cannot be manufactured headlessly at the golden's pinned clock — noted inline).

**Confirmed under (the living version ledger).** The final column records every Things version each law's lock has run GREEN under, seeded `3.22.11` — the golden every law in this register was probed and locked on. This column is the ONE living part of the register: probe *evidence* docs are immutable snapshots stamped with the version they were observed under ([harness](../lab/harness.md) §version-stamping) and are never amended; version confirmation accrues HERE instead. **Amendment rule:** when `npm run lab:regress` passes under a NEW golden ([drift-runbook](../lab/drift-runbook.md) step 3), append that version to every law row whose lock ran green. A law whose lock FAILED under the new golden keeps its stale list unchanged — that stale list IS the drift signal — until the law is re-probed and reconciled, then the new version is appended.

Certified environment: Things **3.22.11 + 3.22.12** · macOS **15.7.7** · DB schema **v26** · golden `things-lab-golden-v2` (Things 3.22.12, derived in-place from v1, clock-pinned 2026-07-05; `things-lab-golden-v1` superseded-pending-deletion). Audited **2026-08-03** (3.22.12 re-certification: `npm run lab:regress` ran GREEN across all suites — u/a/x/o/r/e/p/s + write-layer e2e — with zero verdict/tier/crash deltas, so **every** law's lock ran green and `3.22.12` is appended to all *Confirmed under* cells below; the schema fingerprint stayed byte-identical (`sha256:784bd2f6…`, DB v26) and the sdef byte-identical, confirming a BEHAVIORAL-only update).
