# Decisions register — rulings that are settled, so they stay settled

One line per ruling: **date · ruling · evidence**. This register exists to prevent relitigating decisions that were already made and paid for — a "no" is as expensive to re-argue as a "yes". **Append-only in spirit**: add a ruling when one is made; supersede (never silently delete) an entry only when a later ruling explicitly overturns it, naming the reversal.

**Completed WORK is not recorded here — git is the archive.** This file holds *decisions* (what will NOT be built, which shape won, which knob is canonical), not shipped features (those live in CHANGELOG + the living docs). The short-horizon queue is [up-next.md](../up-next.md); long-horizon strategy is [roadmap.md](../roadmap.md).

Reads stay heading-aware; only `heading.add`-in-an-existing-project is capability-gated. Evidence: [lab/heading-research.md](../lab/heading-research.md).
- **2026-07-09 · AppleScript project-schedule vector — DOCUMENT-ONLY, do not wire.** `schedule to do id <PROJECT>` works via AppleScript (P14-A3), but URL `update-project?when=` is validated and sufficient; a second vector adds compile/matrix surface with zero new capability. Evidence: capability-matrix project-update row.
- **2026-07-14 · Repeating-to-dos hide-flag in `upcoming` — RULED NO.** The `── Repeating To-Dos ──` section stays always-on; the "leftover budget" idea was already the shipped `--limit` behavior. Evidence: CHANGELOG (v0.8.0 window work).
- **2026-07-15 · Tag reorder — ABANDONED by decision (not blocked).** Risky/potentially destructive (silent re-parent hazard, unverifiable nameless positional rows + ubiquitous `TMTag."index"` ties) for little utility; the bar to reopen is a name handle or a validated tie-break oracle. Evidence: [lab/taglab-probes.md](../lab/taglab-probes.md) (TAGORD1), [lab/axdrag2-reorder-certification.md](../lab/axdrag2-reorder-certification.md).
- **2026-07-15 · Drag-ladder rung 2 (scroll-while-held) — SHELVED.** The production ladder stays rung 1 + rung 3; the oddities §9 AX-mirror blanking bug blinds the closed-loop verification the doctrine requires. Revisit only if CC fixes the mirror bug, a non-relaunch heal is found, or a certified travel cap lands. Evidence: [design/ax-initiative.md](ax-initiative.md) build item 3, [lab/axdrag2-reorder-certification.md](../lab/axdrag2-reorder-certification.md).
- **2026-07-15 · `todo.stop-repeat` DROPPED; no `project.stop-repeat`.** The to-do Stop popover is card-only (opens only via mouse double-click, no menu/AX surface — UIC2-d); the project Stop works but stop-then-select CRASHES Things (oddities §7 C5). Evidence: [design/ax-initiative.md](ax-initiative.md), [lab/uic2-project-menu.md](../lab/uic2-project-menu.md).
- **2026-07-23 · Anytime aggregate reorder (`reorder to dos in list "Anytime"`) — DO NOT SHIP.** Non-deterministic (five identical calls → five non-converging orders) AND destructive (strips `area` → NULL on every loose to-do touched, oddities §9c). Area'd loose anytime rows reorder cleanly via the AREA scope; area-less ones use the ANYBNC bounce. Evidence: [lab/anyord-results.md](../lab/anyord-results.md).
- **2026-07-23 · SYNCLAT post-write sync-nudge — NOT JUSTIFIED.** Every write vector advances the sender's `BSSyncronyMetadata` last-attempt signal within ~2–3 s (Things syncs on-change, no periodic heartbeat); the minutes-of-latency Mike saw is receiver-side (no APNs push-wake in a VM). No no-push bug to mitigate. Open residue (on-hardware repro of the sender-side stale panel) lives in up-next. Evidence: [lab/synclat-results.md](../lab/synclat-results.md).
- **2026-07-26 · `TMTombstone` deletion-tracking — DON'T BUILD.** `TMTombstone` is written only for `leavesTombstone=1` rows (repeating-template lineage), NEVER ordinary user deletions, which propagate tombstone-lessly via the Syncrony change-log; a `changeKind:"deleted"` feed on it would silently miss every normal deletion. If deletion tracking is ever needed: a scoped member-set snapshot-diff (the watch primitive). Evidence: [lab/tomb1-results.md](../lab/tomb1-results.md).
- **2026-07-31 · `today ok` / banner-acknowledge — WILL NOT IMPLEMENT.** The banner OK's in-place `start 2→1` (+ `startDate:=deadline`) is not URL-reproducible byte-faithfully (BANNERACK), the OK is not AX-reachable (custom NSView), and it is purely presentational (provisional rows are already full Today members, honestly modeled by the wire `provisional` field + TTY `•` pip); a clamp-to-today approximation was explicitly REJECTED. Revisit only if CC exposes an acknowledge surface. Evidence: [lab/banner1-research.md](../lab/banner1-research.md), [lab/sit3-arrival-evening-lists.md](../lab/sit3-arrival-evening-lists.md).
- **2026-08-11 · `todaySince` (a "time in Today" read axis) — SCRAPPED.** A GUI cross-cohort drag ADOPTS the drop-neighbour's entry cohort (single-row `tiRef` write, older or newer), so `todayIndexReferenceDate` is not a faithful "entered Today" timestamp and cannot back a duration signal. Evidence: [lab/todwire-partial-wires-today.md](../lab/todwire-partial-wires-today.md) (TODWIRE §9y).

## Grammar / contract rulings

- **2026-07-26 · `add` is the canonical create-verb across the operation catalog.** `heading.create` → `heading.add`, `project.create-repeating` → `project.add-repeating`; `make-`/`convert-` stay DISTINCT as transform verbs, the delete family is untouched. Evidence: CHANGELOG (verb harmonization).
- **2026-07-27 · ALPHA-CONTRACT clean-break doctrine — no compat machinery pre-1.0.** The whole contract (TS API, CLI, JSON, MCP, audit records, error codes) is alpha until v1.0; breaking changes are made cleanly, NO shims/alias maps/deprecation windows, and agents must not add or propose them. Flips at v1.0 (teardown tracked in the [roadmap](../roadmap.md) v1.0 checklist). Evidence: AGENTS.md (Conventions), [design/architecture.md](architecture.md) (Alpha contract).
- **2026-07-27 · Heading selection is title-or-uuid — NO index/ordinal addressing.** A heading is itself a reorder target, so an index silently re-targets after any reorder (the unanimous multi-model "reindex hazard"); the checklist `--index` precedent deliberately does NOT transfer. Heading uuids STAY in read payloads (dup disambiguation + script robustness + titleless records). Evidence: [design/cli-vocabulary-study.md](cli-vocabulary-study.md), [design/heading-demotion-and-move.md](heading-demotion-and-move.md).
- **2026-07-27 · `--detach` REMOVED — one spelling per kind.** The detach family is `--no-heading`/`--loose` (to-dos) and `--no-area` (projects); the overloaded `--detach` (which conflated stripping a heading vs stripping a project) is gone. Evidence: [design/heading-demotion-and-move.md](heading-demotion-and-move.md) §4/§5.
- **2026-08-05 · Anchor vocabulary is `--start` / `--end` / `--before <ref>` / `--after <ref>`.** Ratified over the earlier `--first`/`--last` spelling; `--end` is retained alongside `--start` (MCP `reorder` likewise takes `start`/`end`/`before`/`after`), plus `--in <token>` for axis disambiguation. Bare (no position) assembles the block at the earliest movee's slot. Evidence: CHANGELOG (0.15.0 move/reorder vocabulary), [design/heading-demotion-and-move.md](heading-demotion-and-move.md) §4.
- **2026-08-11 · Non-axis orderings are query VIEWS, not a `--sort-by` reorder flag.** A named ordering (deadline order, etc.) ships as its own read view whose identity IS the ordering and is declared NON-SCOPE (`--in <view>` refused) — the `deadlines` view precedent (`deadline ASC`, one comparator shared with `upcoming`). Reorder axes stay the container/bucket scopes only. Evidence: [design/read-shape-doctrine-v2.md](read-shape-doctrine-v2.md) (deadlines addendum), CHANGELOG (`things deadlines`).
- **2026-08-11 · Symbolic-when UPDATE verify is an arrived-date predicate; `evening` stays exact date-equality.** `when: today` on an UPDATE asserts `startDate != null && startDate <= today` (an already-arrived row is not a mismatch); adds and explicit ISO dates keep exact equality; `when: evening` is unchanged, date-anchored to today exactly (the date-anchored evening law is correct as written). Evidence: PR #440, [research/project-update-today-verify-mismatch.md](../research/project-update-today-verify-mismatch.md), `test/engine/write-when-today-verify.test.ts`.
- **~2026-08 · Bare-noun routing of a TAG name (`things <tag>` → a filtered view) — REJECTED; explicit-only remains the open question.** Bare-noun sugar already arbitrates commands/views/areas/projects/to-dos; routing a tag name adds a collision surface where a rename in the user's Things could silently flip which view renders, and a tag uniquely expands to a FILTERED VIEW rather than a single-entity show. The still-open sliver — an explicit sigil (`things @errand`) vs no tag shorthand at all — lives in up-next. Evidence: up-next tag-shorthand item's own reasoning (2026-08-02). *(The bare-noun rejection was not independently pinned to a dated PR in committed docs — see the restructure report.)*
