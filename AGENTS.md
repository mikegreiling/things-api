## Safety rails (non-negotiable)

- **Permissions doctrine** ([docs/design/permissions-doctrine.md](docs/design/permissions-doctrine.md)): no surface may raise a macOS consent dialog outside the two setup ceremonies — everything else detects capability prompt-free and refuses with remediation. A dialog outside a ceremony is a reportable bug.

- **This is a PUBLIC repository.** Everything committed — code, docs, probe evidence, test fixtures, git history — is visible to anyone who cares to look. Never commit: PII; personal task-manager data (no task titles, project names, notes, or any other content derived from Mike's production Things DB — this includes "example" data and test fixtures, which must be fully synthetic, never copied or paraphrased from the real database); account credentials of ANY kind, ephemeral or otherwise (throwaway lab accounts, disposable inboxes, one-time codes included — record those only in gitignored `lab/artifacts/`). Remember that git history is public too: redacting a file later does not unpublish it, so get it right before committing.
- **Production Things (this host) is READ-ONLY for agents.** Reads go through the `things` CLI's read verbs or `scripts/prod-read.sh` (one stable command shape — ad-hoc shapes re-trigger macOS consent). **No agent — orchestrator or delegate — writes to, drives the GUI of (`--dangerously-drive-gui`, any ui-vector operation), sends AppleEvents/keystrokes/pointer events to, or changes the installed helpers of the maintainer's production Things without his EXPLICIT, PER-RUN sanction.** That includes synthetic-content smokes and the release gate's field-shaped run: the maintainer performs those himself, or time-boxes a sanction with `scripts/sanction-prod.sh` from HIS terminal — never from an agent's shell, and a sanction given for one run does not carry to the next. Enforced on Claude Code by the PreToolUse hook `.claude/hooks/prod-things-guard.sh` (refuses unsanctioned host-side write/GUI/helpers commands; Tart/ssh lab commands pass). A refused command is reported, never rephrased around. Never point new binary shapes at the prod container (even `doctor`). (2026-09-03: a release delegate GUI-drove the maintainer's production Things unattended while he was working at the machine — the orchestrator had generalized a one-time, maintainer-present smoke into a standing authorization. This rule exists so that never recurs.)
- Writes go exclusively through official app surfaces (URL scheme / AppleScript / Shortcuts) — never direct SQLite writes. All write probing happens in disposable Tart VMs (`docs/lab/`).

## Conventions

- **ALPHA-CONTRACT (pre-1.0) — break freely, add NO compatibility machinery.** The ENTIRE contract — programmatic TS API, CLI vocabulary, JSON shapes, MCP tools, audit-trail record format, and error codes — is ALPHA until package **v1.0** ships. There is exactly ONE consumer (the maintainer). Until v1.0, breaking changes are made freely and cleanly: **do NOT add — and do NOT propose — compatibility shims, alias maps, deprecation windows, or legacy-format readers.** Such machinery is pollution; delete the old shape outright and let stale data/callers fall away (e.g. pre-rename audit records simply become unrecognized and non-undoable — that is acceptable and correct). This rule exists so the point never has to be re-argued per change. At v1.0 this FLIPS — compatibility discipline begins — and **this doctrine MUST be removed** as part of the v1.0 release: `grep -rn ALPHA-CONTRACT` to find every signpost (this entry, `docs/design/architecture.md` §Alpha contract, and the v1.0 checklist in `docs/roadmap.md`) and delete them. See [docs/design/architecture.md](docs/design/architecture.md) (Alpha contract).
- Verify `npm run check` by EXIT CODE, never by grepping piped output. Run `npm run fmt` before committing (oxfmt also formats committed JSON).
- Feature branches (`mg/<topic>`), PRs for the audit trail, self-merge after CI is fine.
- **Release gate — no version is tagged until the FIELD-SHAPED run is green.** Three conditions, all of them: **(a)** `npm run lab:regress` exits GREEN on a GUI host (all eight suites + the guest e2e); **(b)** every operation whose driver / vector / recipe / deputy-facing code changed in the batch has been run END-TO-END at least once **THROUGH THE DEPUTY** (helpers installed and enabled) using the NORMAL CLI syntax against synthetic content — the field-shaped path, not direct script execution; **(c)** for GUI-driven (ui-vector) operations, at least one of those runs is on a **REAL DISPLAY** (the maintainer's host or the framebuffer/HID rig), because a headless clone cannot reproduce real-hardware rendering and latency. Lab probes stay direct-execution by design — that is what they are for — but certification of a RELEASE is the field-shaped run. (Two lab-green/field-red releases in five weeks bought this rule: 0.19.2's window/focus census stalled ~15s per inspection on real hosts and did not reproduce headless at all (#629, [lab/fgrd2-census-hardening.md](docs/lab/fgrd2-census-hardening.md)), and 0.20.7's observer sidecar reached its socket through `do shell script`, which the deputy's broker refuses by design — green on every lab probe, broken on every helpers-enabled host.) The drill, in full: [docs/reference/release-checklist.md](docs/reference/release-checklist.md).
- **Issue lifecycle — `Refs #N`, NEVER `Fixes #N`.** A PR that addresses a tracked issue references it as `Refs #N` (or plain `#N`); `Fixes`/`Closes`/`Resolves` auto-close the issue the moment the PR merges and are never used here. A GitHub issue is closed ONLY after the reporter confirms the fix resolves it — for a field bug, the maintainer's own re-run on the machine that hit it — because lab certification cannot reproduce real-hardware conditions, so "merged" ≠ "fixed" for a field-reported bug. A merge is not confirmation.
- All consumer-facing copy (CLI `--help`, MCP tool descriptions, exported JSDoc) follows [docs/design/surface-copy.md](docs/design/surface-copy.md) — behavior and side effects only; banned-vocabulary regression tests enforce it.
- Guest e2e bundles ship node + dist + commander ONLY — heavyweight deps (MCP SDK, zod) must stay lazily imported from CLI actions.
- **Consumer boundary (air gap):** `src/cli/**` and `src/mcp/**` are pure consumers of the library through the single entry point `src/index.ts` — never import a library internal directly (intra-surface presentation imports are fine). Enforced by `test/unit/import-boundary.test.ts`; see [docs/design/architecture.md](docs/design/architecture.md) (Consumer boundary).
